# GPS time, real-time clock and automatic time zone — design

Status: approved in conversation 2026-10-26; awaiting written-spec review.

**Amendment (2026-10-26, from the user): the time zone is manual only.** The
automatic zone from GPS is removed: the boundary data (§5), the lookup, the
zone mode and the saved automatic zone are gone. The user picks the zone from
a curated list (`lib/core/src/tz/zones.cpp`) on the setup page, in web config
and in device Settings, or types a POSIX string in web config. GPS still sets
the clock, and the GPS powers on only for the time. Sections below that
describe the automatic zone are superseded.

## 1. Goal

Keep the clock right on every board with or without Wi-Fi, and set the time
zone automatically from where the device is, offline. Today the clock comes
only from SNTP, started once in `wifimgr::begin` (`configTzTime` with
pool.ntp.org and time.google.com), with a manual POSIX TZ string from web
config.

## 2. Decisions (from the user)

| Topic | Decision |
|---|---|
| GPS use | Time, plus fix and satellite status, plus automatic time zone from position |
| GPS power | On only until the clock (and, for Automatic zone, a position) is set; re-check every few hours |
| RTC | Keep time in the M9's PCF8563 across reboots |
| Time zone lookup | Bundled simplified IANA zone boundaries in flash, generated by a script |

## 3. Hardware (`src/hal/board.h`)

| Function | M9 | Wio Tracker L2 |
|---|---|---|
| `bool hasGps()` | true | true |
| `void gpsPower(bool on)` | CC1167Q: enable GPIO 11 (active LOW), reset GPIO 5 (active HIGH, through an NPN); the VEXT rail (GPIO 18) is already on | L76K: expander bits 13 (power) and 9 (reset, active HIGH) |
| `size_t gpsRead(uint8_t* buf, size_t n)` | UART1, RX GPIO 2, TX GPIO 3, 115 200 baud | UART1, RX 18, TX 17, 9 600 baud |
| `bool rtcRead(int64_t& epochUtc)` / `bool rtcWrite(int64_t)` | PCF8563 at 0x51 on the peripheral I2C bus (SDA 7, SCL 6); read fails when the chip's voltage-low flag is set | returns false (no RTC) |

Pins come from `../camillia/camillia-mt/src/hal/hw_m9.h` and
`hw_wio_tracker_l2.h`. `gpsRead` never blocks. Boards without GPS or an RTC
return false/0.

## 4. Portable logic (`lib/core`, host-tested)

### 4.1 `gps/nmea.{h,cpp}`

A streaming parser fed bytes. Checks the checksum; parses RMC (UTC date and
time, valid flag, position), GGA (fix quality, satellites used) and GSV
(satellites in view, summed over talkers). Produces a `GpsState{fix, sats
used, sats in view, utc valid, utc epoch, lat, lon, ms of last fix}`. Ignores
unknown sentences and bad checksums.

### 4.2 `time/clock_policy.{h,cpp}`

Pure decisions, driven by `tick(nowMs, inputs)`:

- **Sources, best first:** NTP, GPS, RTC.
- **Boot:** if `rtcRead` succeeds with a plausible time (2025 or later), set
  the system clock from it (source "RTC").
- **NTP:** restarted on every Wi-Fi station connect (`esp_sntp` stop/start),
  so a device that booted offline syncs as soon as it can. The SNTP
  time-sync callback reports success to the policy.
- **GPS:** a valid RMC time sets the clock when the clock is unset or its
  last sync is over 1 hour old and NTP hasn't synced in that hour (GPS never
  fights a fresh NTP time).
- **RTC write:** after every NTP or GPS sync, at most once an hour.
- **GPS power:**
  - On when the clock is unset or its last sync is over 6 hours old, or when
    the zone mode is Automatic and there is no position from the last 6 hours.
  - Off once those needs are met.
  - A search gives up after 15 minutes and retries 1 hour later.
- Outputs: `setClock(epoch, source)`, `writeRtc(epoch)`, `gpsPower(on)`,
  plus a status snapshot for the UI.

### 4.3 `tz/tz_lookup.{h,cpp}`

- Input: a read-only blob (see §5) and a position.
- A 1°×1° grid index lists the zones whose boxes overlap each cell; cells
  inside one zone store it directly. Point-in-polygon (even-odd) on the
  candidates only.
- Result: an IANA zone name and its POSIX TZ string.
- No zone (open ocean): `Etc/GMT±n` from the longitude (n = round(lon/15),
  sign inverted as POSIX requires).
- The zone is recomputed only after the position moves more than 10 km from
  where it was last computed, or on the first fix after boot.

## 5. Data generation

- `scripts/tzgen.py`, run with `python3 -I`, reads:
  - timezone-boundary-builder's `timezones-with-oceans` GeoJSON (or the
    no-oceans release), downloaded outside the repo like the Terminus fonts;
  - the POSIX TZ string for each zone, taken from the last line of the
    system's compiled tzdata (`/usr/share/zoneinfo/<zone>`).
- It simplifies each polygon (Douglas–Peucker, tolerance about 0.01°, about
  1 km), quantises coordinates to int32 micro-degrees deltas, builds the grid
  index, and writes `src/tz/tz_data.h` (a `const uint8_t[]` in flash) with a
  version and source-release header. Target size: 2 MB or less.
- A small hand-made fixture blob (three square zones) is used by the native
  tests, so the tests don't depend on the generated data.
- Attribution (ODbL, timezone-boundary-builder / OpenStreetMap contributors)
  goes in `docs/USE.md`, `README`, and the web config footer.

## 6. Settings, UI and web

- Settings fields: `tzMode` (Automatic | Manual, default Automatic on boards
  with GPS, Manual otherwise), the existing `tz` (manual POSIX string, also
  the fallback until a zone is found), `tzAutoName` (last found zone name and
  its POSIX string, so it survives reboots), `ntpServer` (default
  `pool.ntp.org`; the second server stays `time.google.com`).
- Device Settings screen:
  - `GPS` — off / searching m:ss / fix, N of M satellites;
  - `Time` — the source and when it was last synced (NTP, GPS, RTC, not set);
  - `Zone` — the zone name and "(auto)" or "(manual)".
- Web config: the same status lines; a zone mode choice (Automatic from GPS,
  or Manual with today's picker); the NTP server field (validated: host name
  characters only, 1–63 characters).
- Backups include `tzMode` and `ntpServer` (the backup spec's YAML gains
  those keys).

## 7. Privacy

- The position is never sent anywhere, never stored, and never logged. Logs
  say only fix yes/no, satellite counts and the derived zone name.
- Only the zone name and POSIX string are saved.

## 8. Testing

Native:

- NMEA: valid RMC/GGA/GSV, bad checksum, no fix, split across reads,
  unknown talkers.
- Clock policy: boot from RTC, NTP beats GPS, GPS after NTP goes stale, RTC
  write throttling, GPS power on/off, 15-minute give-up and 1-hour retry,
  Automatic zone keeping GPS on until a position.
- TZ lookup on the fixture blob: inside, outside, on an edge, a hole, the
  ocean fallback for both hemispheres, and the 10 km rule.

Builds: `m9`, `m9_fake`, `wio_l2`, `wio_l2_fake`. The fake builds keep their
fixed clock and report a fake GPS.

Hardware (`docs/TESTING.md`): the clock right after a reboot with Wi-Fi off
(RTC, M9); GPS fix outdoors with Wi-Fi off sets the clock; the zone matches
the location; GPS turns off after; the NTP server field works.
